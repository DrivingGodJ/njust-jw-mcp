# 技术笔记

这些是逆向过程中踩过的坑。记录下来主要是为了下次学校改版时能快速定位问题，也方便想给其他学校做同类工具的读者对照。

## 登录：CAS 的密码加密

统一身份认证（Apereo CAS）的登录页把密码加密交给了前端：

- 页面 DOM 里有 `pwdEncryptSalt`（32 位随机串，每次加载都变）；
- 前端用 `AES-128-CBC / PKCS7` 加密，`key = salt`，`iv` 是另一个 16 位随机串；
- 明文是 `64 位随机串 + 密码`，结果做 base64 后放进 `password` 字段。

关键点是**IV 不需要知道**。CBC 模式下 IV 只影响第一个分组，而前 64 个字符（正好 4 个分组）在服务端解密后会被丢弃，所以随便填一个 16 字节 IV 都能通过：

```bash
openssl enc -aes-128-cbc -K "$(printf %s "$SALT" | xxd -p)" \
  -iv "$(printf %s "$IV" | xxd -p)" -a -A
```

`-a` 是 base64，`-A` 让输出不换行，明文从 stdin 喂进去。

**另一个坑**：请求登录页时 jar 必须是空的。带着旧 `CASTGC` 去请求 `/authserver/login`，CAS 会直接 302 回 `service`，根本拿不到 `pwdEncryptSalt`，于是报「找不到 salt」。

## 从 CAS 到教务

拿到 `CASTGC` 只是第一步，教务系统（强智）并不直接吃这个 ticket。两个能用的入口：

- 教务：`bkjw.<domain>/njlgdx/indexsso.jsp` — 主动跳 CAS，回跳后种下教务自己的会话；
- 学工：`xg.<domain>/sso` — 同理，但学工还有一层应用级 token，见下文。

访问这个入口时，`JSESSIONID` 会随回跳落进 cookie jar。**实测只需要 `JSESSIONID`**，`MOD_AUTH_CAS` 不必带上。

教务的 `JSESSIONID` 是会话级的，约 4 小时失效，比 CAS 的 30 天短得多。所以工具在收到登录页 HTML 时会识别出来，重新走一次自动登录。

## 强智的表单陷阱

强智（Qiangzhi）教务系统的页面上经常出现这种表单：

```html
<form action="" method="post">
```

`action` 是空的，真正的提交地址写在内联 JS 里，长这样：

```javascript
function querypyfa() {
  document.getElementById('Form1').action = '/njlgdx/pyfa/pyfa_query';
  ...
}
```

**直接 GET 列表页永远返回 `tables: 0`**，因为是 AJAX 型页面，数据要靠 POST 到那个隐藏地址才拿得到。遇到「页面能打开但没数据」，先去翻页面内联 JS 里的 `action=` 赋值。

## 学期下拉不是全集

培养方案的「学年学期」下拉只列到当前学年 +2，但把 `2029-2030-1` 这样的值直接 POST 进去照样有数据。所以别用下拉做枚举，**按入学年自己生成**：每学年 `-1 / -2 / -3`（第三学期是暑期短学期，通常为空）。

## 专业是三级联动

`xsyx`（院系）→ `xsnj`（年级）→ `xszy`（专业）三级，每一步都要 POST 回本页拿下一步的选项，不能跳步。专业的值是一串哈希，只能从页面上抓，不能猜。

## 表格解析

所有列表页共用同一套结构：`table#dataList`，`th` 是表头、`td` 是数据行，页面编码 UTF-8。部分页面（课表）用的是网格 `div`，见下一条。

## 课表是网格不是表格

课表页有 3 张表，真正有内容的是第 2 张：6 个数据行 = 六大节 × 7 列（周一到周日）。每个格子里是 `<div class="kbcontent">`，节次、课程、周次、教室都挤在同一个格子里的换行文本中，需要按固定顺序拆。

## 教室占用是 36 列

教室查询返回的网格是 `1 + 7 × 5 = 36` 列：第 1 列是教室名，后面 7 天 × 5 个时段。空格表示空闲，有内容表示被占用。

## 学工与教务不是一回事

同一所学校的两套系统，数据口径不同：

- **教务（bkjw）**是权威源：课表、成绩、考试、学籍、培养方案都在这里；
- **学工（xg）**是另一套（zovecenter 微前端 + 网关），课表可能漏节次、缺公共课。

需要交叉验证时，两个都查一遍最稳。学工网关的每个业务接口有各自的 `H-Zove-AppKey`，**不能互相套用**，换业务必须从页面重新捕获。

## 该不该写备忘录 / 日历

工具本身只返回结构化数据，不碰你的日历和备忘录。要落盘可以配合同一个作者的两个 MCP：

- `local-calendar`（EventKit）——课表、考试写进系统日历，iCloud 自动同步手机；
- 备忘录写入走 AppleScript，注意 `osascript` 控制 Notes 需要「隐私与安全性 → 自动化」授权，**未授权时它不报错而是直接挂住**，调用方必须自己加超时。
